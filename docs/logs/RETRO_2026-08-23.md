- Each user item mapped to a concrete screen or service instead of a vague “quality” rewrite.
- Chatbot was researched and parked. Voice was gated as Coming soon instead of a fake agent.
- Production AdMob IDs replaced leftover test-publisher / empty dart-define risk on the results + quota path.
- Project logs were updated the same day, including residual risks.

## What was messy

- **Partial first pass.** The 27-bug change compiled in English, then non-en locale Dart was missing five new getters (`goalTooVague`, `learnPastPathsTitle`, `settingsDailyQuizFrequency`, `settingsAlarmSound`, `interviewVoiceComingSoon`). A second pass stubbed them in English. Non-en ARBs still omit the keys.
- **Locale compile gaps.** Regenerating l10n from ARB will drop those Dart getters until every locale ARB defines them.
- **Analyze-only verification.** BUGFIX_LOG Verified line is `flutter analyze` on touched paths. No widget/integration tests for the batch.
- **No emulator pass.** Emulator setup was attempted earlier in the day; the 27-bug session did not run the app on a device or AVD. Ads fill, alarm channels, swipe-back, and notifications are unproven on hardware.

## What to do differently next time

- Add new l10n keys to `app_en.arb`, every locale ARB, and generated Dart in the **same** change. Do not ship a feature string in English-only Dart.
- Budget a device smoke after any batch that touches overlays, ads, notifications, or grading. Analyze is not enough for those.
- Keep “Coming soon / backlog only” decisions in [BACKLOG.md](../BACKLOG.md) when they happen, not as a later cleanup.
- Split hosting/store copy from app behavior PRs when possible (that part of this day was cleaner).
